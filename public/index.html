I'm Lucas Gundry. I work on AI security and enterprise security.

I'm building a homelab to show what I can do. It has a fake company in Okta, a SIEM in Elastic, detections I've tested, and an AI triage agent with guardrails that posts to Slack.

Read the write-ups

The lab

Everything runs on one mini PC at home. The story is a fake shoe company that gets attacked. My detections should catch the attack, and the agent helps me investigate it. The agent can read data and suggest what to do. I approve anything that would change an account.

Done so far:

  • An Okta directory for the fake company, with 30 users in 8 departments and 13 groups, all managed in Terraform.
  • Okta's audit log streams into Elastic. Every hour a separate check confirms each event arrived, matching by event ID.
  • Detections written as code, with test cases that run on every pull request: failed Okta sign-ins, SSH failures and sudo as another user are live. An MFA push fatigue rule is written and tested, but not turned on yet.
  • Nightly snapshots of the SIEM, with a daily check that emails me if a backup fails or the check stops reporting.
  • An AI triage agent that checks for new alerts every 5 minutes, investigates with read-only tools and posts a verdict to Slack. It's capped at 15 tool calls per run. Its tests assume the model obeys injected text, then check that code rejects what it asks for.
  • Personal data leaves the agent's tools only as stand-ins. A separate check emails me if the agent stops, fails or is about to lose a key.

Write-ups

  • Keeping personal data out of an AI triage agent

    My first design hid only the values I'd listed, and it leaked twice. Stand-ins now replace every address, place and outside email before the model or Slack sees them.

  • An MFA fatigue detection, and the test data I guessed wrong

    A push-bombing rule as code, tested in CI. One real push showed my test data used the wrong event for a denial.

  • Knowing when the triage agent stops

    A separate read-only check that alerts when the agent stops ticking, when a run fails, or a week before a key expires.

  • Okta in Terraform, and a detection I tested both ways

    I manage a fake company's Okta with Terraform and wrote a failed sign-in rule. I tested the cases where it should fire and the cases where it shouldn't.

  • Missing logs that weren't missing

    A log line said events were being dropped. I wrote up a root cause, then measured it and found I was wrong.

  • Read-only monitoring and backup alerts

    A monitoring role I tested by what it's refused, and backup alerts. One alert test caught a config mistake I'd made.
