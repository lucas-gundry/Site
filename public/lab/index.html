Investigate an employee

Bionic Footwear is a fictional shoe company with 40 employees and a week of made-up logs: Okta sign-ins, laptop alerts, and file sharing. Pick someone and watch a triage agent work through the evidence. It explains each step, scores the risk, and recommends an action. It can't act on its own.

What this shows: how I want an investigation agent to behave: read-only lookups, a reason for every finding, a score from fixed rules, and a person approving anything that changes an account.

The "agent" here is plain JavaScript rules, not a model, so every run is the same. My real lab agent uses a model with the same limits.

        How the simulation works

        • The dataset is generated by a seeded script, so it's the same every time. Emails use the reserved .example domain and addresses come from documentation ranges. No real people, companies or networks.
        • Every "tool" is a read-only lookup on that file. Nothing leaves your browser: the page's security policy blocks every outside request.
        • Findings and points come from fixed rules. Each finding names the events behind it.
        • Approving does nothing here. In my lab's design, a separate program (not the agent) would run exactly the approved action and check that it happened.
